EMERGENCY EVENTS · PLUGIN OVERVIEW

动态危机响应。
不是定时随机事件。

Emergency Events 面向 SCP: Secret Laboratory / EXILED 持续观察整场回合，再依据真实战局决定设施需要何种响应、哪些事件具备资格，以及它们应以多大规模出现。

查看 D-LRC 系统 了解核心模块
ROUND DIRECTOR / LIVE MODEL

每次事件都先问：
现在的局势允许它发生吗？

  1. 01读取回合状态LIVE
  2. 02计算控制与响应等级D-LRC
  3. 03识别当前危机与设施失序CRISIS / FDI
  4. 04筛选并重新验证候选事件DIRECTOR
  5. 05执行、提交或安全回滚FAIL-SAFE
SYSTEM MAP

一套围绕真实战局运行的模块化框架。

每个模块负责一种事实或决策，既能独立演化，又共同服务于“让特殊事件成为战局的一部分”这一目标。

M01 / ROUND CORE

人口规格锁定

回合开始时根据 16–45 名玩家锁定 E–A 人口档位，整局保持统一的事件规模与编制规则。

M02 / REINFORCEMENT

与原版协作

保留原版 Primary Wave 的选择、计时与 Spawn，只在外围施加上限、记录和必要约束。

M03 / D-LRC

动态响应代码

通过人口档、响应等级与危机标签描述当前设施状态，并在回合中持续重新评估。

M04 / CRISIS + FDI

危机与失序

识别 BIO、SYS、CON、SEC、GOI、WAR、END 等危机，同时记录设施失序的长期影响。

M05 / EVENT DIRECTOR

事件导演

依据响应等级、危机、人数、FDI 和事件限制选择候选，并在执行前再次确认条件。

OBSERVER / TELEMETRY

可解释的平衡数据

读取正式系统的结果记录遥测，不制造第二套真相，为后续平衡与实服验证提供依据。

DECISION CHAIN

事件不是被抽出来的。
它需要先取得资格。

从候选到提交的每一步都保留重新验证与回滚出口，避免上一秒成立的条件在下一秒失效后仍被强行执行。

01 / OBSERVE

读取事实

人口、SCP 威胁、增援表现、时间与战略风险共同构成当前局势。

02 / EVALUATE

判断控制

Response Score 先形成理论等级，再由 Control State 限制最终响应上限。

03 / QUALIFY

检查资格

危机标签、专业响应、设施状态、可用玩家与人口 Profile 必须同时匹配。

04 / REVALIDATE

执行前复核

事件选中后仍会检查人员、危机与响应等级，条件失效就安全终止。

05 / COMMIT

提交或回滚

只有真正 Commit 的专业响应才消耗资格，StartFail 与 Rollback 不会浪费机会。

OPERATING PRINCIPLES

系统要响应局势，也要保护一整局游戏。

Emergency Events 设计为尽量接入原版规则，而不是重写整套 SCP:SL；外围功能失败也不应拖垮核心 Gameplay。

Vanilla-Friendly

Primary Wave 的阵营选择、Token、原版计时、装备与 Spawn 仍由原版负责。插件只记录和约束，不把原版系统整体推翻。

Fail-Safe

遥测写入、候选事件或环境验证失败时，系统记录原因并继续运行；事件可回滚，Director Busy 会被释放。

Population-Aware

同一个事件可以有 E–A 五套人口 Profile。人数不足时只在当前档位内 Downscale，绝不偷偷换到另一人口档。

Observable & Privacy-Aware

日志解释 D-LRC、危机、FDI 与事件为何发生，同时遥测不记录 SteamID、IP、昵称或跨局身份。

CURRENT STATUS

当前能力与边界。

概览页只展示当前确认的状态。自动化通过与框架就绪不等同于所有内容已经完成真人实服验证。
