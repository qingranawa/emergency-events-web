Emergency Events
丰富阵营。更多动态事件。
每一局，都可能
走向不同方向。

Emergency Events 为 SCP: Secret Laboratory / EXILED 带来多阵营、多类型的动态事件框架。事件不会按固定时间表出现，而是根据这一局正在发生的事情，决定谁能介入、以什么方式介入。

DYNAMIC EVENTS

事件不只是“刷一队人”。

每类事件都有自己的资格条件、目标和影响方式。系统先理解当前回合，再从可用的内容包中选择适合此刻的介入。

ARCHITECTURE READY
A ROUND WITH EMERGENCY EVENTS

一局游戏不会按照固定剧本发展。

插件从开局就改变力量关系，再根据战局变化筛选后续事件；每次介入都可能成为下一次判断的输入。

ROUND OPENING / OPENING GAMEPLAY

安保人员与混沌渗透者以对称轻武装开局，分别出生到 LCZ A/B 电梯，争夺武器库与权限。SCP 数量随人数变化，第二只 SCP-939 是随机候选，不是固定必出。

FACILITY MEMORY / FDI

FDI 不是快照重算，而是 PreviousFDI + EventDelta 的持续记忆，并以 LOW / MEDIUM / HIGH 表示失序程度。安静且局势允许时才进行 Order Recovery，三档恢复速度不同。

PROFESSIONAL RESPONSE

某些事件不是普通事件，而是针对特定危机的专业响应。指定 D-LRC 等级与危机标签同时满足时，事件才有资格介入。

POPULATION PROFILE

同一个 EventId 不需要复制为 E/D/C/B/A 五个事件；人口差异由 Profile 调整规模、编制和装备，始终留在当前人口档位内。

01 / OPENING

普通开局

安保人员、混沌渗透者与 SCP 开始争夺设施。

02 / PRESSURE

局势开始恶化

SCP 威胁、基金会损失或设施异常不断改变局面。

03 / CRISIS

新的危机形成

某种危机逐渐满足专业响应条件。

04 / INTERVENTION

新的阵营介入

适合当前局势的专业单位或第三方事件取得资格。

05 / AFTERMATH

战局再次改变

新事件改变力量关系，并影响下一次判断。

EVENT QUALIFICATION

事件不是被抽出来的。
它需要先取得资格。

事件开始前会重新确认人数、危机与当前响应状态；条件失效时安全取消，不强行打断正在进行的回合。

01 / OBSERVE

观察当前战局

读取回合正在发生的事实与力量变化。

02 / EVALUATE

判断当前响应与危机

确认当前状态是否允许新的介入方式。

03 / QUALIFY

找出适合的事件

让真正匹配当前局势的内容进入候选。

04 / REVALIDATE

事件开始前再次确认

条件变化就退出候选，不把过期判断带入回合。

05 / COMMIT

正式介入或安全取消

只有确认提交的事件才会改变战局。

RUNTIME AVAILABLE
WHY EMERGENCY EVENTS

让每一局都留下新的问题。

它把动态事件放进真实战局，同时为服主、内容作者与后续开发保留清晰边界。

Multi-Faction

为不同组织与专业单位提供统一事件框架。

Situation-Aware

事件根据当前战况获得资格，而不是固定时间随机抽取。

Population-Aware

同一个事件可以根据人口档位改变规模、编制和装备方案。

Vanilla-Friendly

尽可能与原版 Primary Wave 协作，而不是重新实现整套 Respawn。

Runtime Safe

事件启动前重新检查人数、危机和响应状态，条件失效就安全退出。

Modular

事件内容与核心 Director 分离，新内容不需要改写核心判断。

Observable

日志和 Telemetry 可以解释系统为什么做出某个决定。

Data-Driven

Balance Harness 覆盖 E–A 全档模拟、Semantic Scenarios 与多 seed；Telemetry 再接入真实服务器数据，不凭感觉直接改阈值。
