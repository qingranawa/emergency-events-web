# Emergency Events 官网文案维护规范

## 文案目标

官网首先要说明插件是什么、解决什么问题、当前做到哪一步。页面职责是介绍模块和运行契约，不是写宣传故事，也不是把源码字段直接堆给访客。

Emergency Events 的主叙事是：

> 插件记录一局游戏的事实，计算当前响应状态，识别危机并筛选候选；条件变化时，开始前重新检查。

## 页面职责

| 页面 | 主要问题 | 适合内容 |
| --- | --- | --- |
| 首页 | 这个插件是什么、有什么用 | 回合接管、局势记录、响应判断、事件筛选、当前状态 |
| D-LRC | 状态代码每一部分代表什么 | 人数档位、响应等级、危机标签、分数、更新周期 |
| 运行方式 | 各模块怎样协作 | 回合核心、原版增援、响应判断、危机识别、FDI、事件筛选、事件内容 |
| 阵营参考 | 页面中的组织和单位是什么 | 世界观资料、潜在接入对象、生产内容状态 |

## 模块说明模板

每个模块的标题和正文按以下顺序写：

1. 模块名称。
2. 模块职责。
3. 输入事实。
4. 输出结果。
5. 使用结果的下游模块。
6. 当前实现状态。

例如：

> FDI（设施失序记录）用 0–100 表示当前设施秩序状态。它读取当前设施存量和最近事件变化，按时间累计或恢复，结果提供给普通支援的来源选择。

## 标题规范

标题使用简短的模块名称或职责名称：

- 回合核心
- 原版增援接入
- 响应判断
- 危机识别
- 设施失序记录
- 事件筛选器
- 事件内容包
- 运行记录

标题不要使用长句、问句、口号或大白话。说明性内容放到标题下面的描述中。

## 语言规范

- 中文作为正文主语言。
- `D-LRC`、SCP 编号、`BIO/SYS/CON/SEC/GOI/WAR/END`、RemoteAdmin 命令、配置字段和源码路径保持原样。
- 英文原名只在代码示例、字段说明或第一次出现时保留。
- 避免“是……而不是……”“不是……也不是……”“不等于……”等防御性句式。
- 不主动为读者没有提出的误解添加反例。
- 直接说明模块的对象、输入、处理、输出和用途。

## 已确认的模块事实

- 回合核心：判断是否接管，锁定开局人数档位和开局编制，负责本局生命周期清理。
- 原版增援接入：保留原版阵营、职业、装备、玩家选择和出生流程；记录实际波次并应用人数上限。
- 响应判断：读取 SCP、基金会、增援、时间和战略危险，计算响应分数、局面状态和最终响应等级。
- 危机识别：七类危机检查器读取同一份回合记录，维护危机状态和每次危机的编号。
- FDI：用 0–100 表示设施秩序状态，读取当前设施存量和最近事件变化，结果提供给普通支援来源选择。
- 事件筛选器：读取已确认的回合事实，检查事件条件、人数计划、来源和生命周期，并在启动前重新确认。
- 事件内容包：未来负责角色、装备、出生点和实际事件执行；当前正式生产内容数量为 0。
- 运行记录：只读保存响应判断、危机、设施、增援和回合摘要。

## 状态边界

必须区分以下状态：

- 已完成：当前源码和契约能够确认。
- 框架完成：接口和生命周期存在，但正式内容或平衡仍未完成。
- 开发中：后续内容正在制作。
- 按设计暂缓：当前版本明确不实现。
- 等待验证：需要真人回合或真实客户端验证。
- 模拟示例：只用于解释状态链，不代表生产事件或实时服务器。

## 发布前审查

- 第一屏是否用一句话说明插件是什么。
- 每个模块是否回答“是什么、读取什么、输出什么、给谁用”。
- 标题是否短、准、可导航。
- 正文是否存在连续反例、过度辩解或无关英文。
- 是否把模块框架误写成生产事件。
- 是否保留已经确认的品牌 logo、品牌副标题和 D-LRC Hero 视觉表达。
- 是否在桌面和移动视口检查中文标题换行。
